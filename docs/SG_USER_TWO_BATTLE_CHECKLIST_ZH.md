# Smart Guard — 两场战斗操作卡（执行前必须配好包，不是现在要求测试）

> 实机预算严格两次：T1 原生观察，T2 通过离线门槛后的候选验证。T2 若没有候选就取消。每次仅 **一次启动、一场自定义战斗**；不要求中途退回菜单换 MOD。

## 测试包要求（开发侧负责）
- T1：SG_FLIGHT_RECORDER_BASELINE.pack。必须包括一套完整 9 模块观察器和非空 script/enable_console_logging 文件，以及 ModLog 双通道兜底，**无 halt/attack/goto 控制指令**。
- T2：保持同一观察器 commit 和哈希，只额外安装受验证的 SG_CANDIDATE.pack（可能包含最小 DB 差异 + 受控转火；功能模块与记录器分离）。
- 同时必须由开发侧提供 game-build 指纹、文件 SHA、离线解析器和现成测试阵容/地图推荐，完整验证后才发给玩家。每次只回收一组日志与连续录屏。

## T1 — 综合诊断，做完这些就结束，不加场
准备：禁用 v2.1 Smart Guard 和其他主动发令 MOD。使用固定陆战地图和阵容：2 支相同弓手、1 支枪兵、1 支火炮、1 支前排友军遮挡、敌方至少两类目标。不要选需要复杂攻城机制的地图。

1. **自检/标记**：部署期依次选中四个监控单位，录屏并截图初始部署；正式开战。
2. **开火基线**：弓手与枪兵 Guard+Fire at Will，正面正常射击，观察一整次开火—装填—再开火循环。
3. **友军挡枪线**：把枪兵放在友军背后，对正面敌人射击，观察是否有黄色受阻提示与自动寻位。
4. **地形遮挡**：在同一地图的预定坡地/地形遮挡处让弓手射击，观察状态与走位。
5. **转向/射程**：选择侧后方目标、再选择超出射程目标，记录转身与走位。
6. **选敌/手动 RMB 目标**：先允许自动开火选敌，再 RMB 人工指定另一个目标，观察是否恢复/走近/换目标。
7. **连续指令**：RMB 地面移动、RMB 拖拽改变阵宽/朝向、Shift 连续两个移动点。
8. **特殊命令**：火炮手动攻击地面；分别切换 Guard、Fire at Will、Skirmish；最后才做撤退以避免影响前面场景。
9. **结束**：正常结束战斗。提交完整战斗脚本日志（优先 script_log；同时附 lua_mod_log 如有）、完整录屏、游戏版本、启用 MOD 截图和地图部署截图。

每一步如条件因敌军 AI 变化不可复现，标记“未复现”继续下一个；**不重启、不补做另一场**。

## T2 — 集成验收，最多同样一场
使用相同地图/阵容/部署；2 支相同弓手作为 CONTROL 与 PILOT。

1. 选择相同监控单位，确认记录器未变、候选包已启用。
2. 前方无遮挡射击 + 装填，确保正常输出。
3. 复刻友军和地形遮挡，比较 CONTROL 与 PILOT：是否真正开火、是否换目标、是否自行走位；若 T1 否决自动转火，跳过此功能而仅观测。
4. 复刻侧后方转向，验证 DB 射界/转轴变更（仅在当前 schema 已确认且候选存在时）。
5. 在 PILOT 启用时直接 RMB 移动、拖拽阵型、右键敌人（含超射程目标）、Shift 两点 MOVE，任何被覆盖都算失败。
6. 火炮攻击地面、守卫/散兵/自动射击模式、最后撤退。
7. 正常结束并提交同样的日志/录屏/版本/模组信息，**不要求第三次**。

## 对玩家的承诺
- 不要求玩家修改、替换或重新编译观测器，不要求手动试 CCO Key。
- 所有接口失败都必须写 UNAVAILABLE 而不是崩溃/伪造 false。日志自带版本/seq/最终统计，解析器能处理部分截断。
- 测试最多两场，结果若不完整，开发侧如实写 UNKNOWN 并改走离线/native 研究，而不是继续追加实机。
